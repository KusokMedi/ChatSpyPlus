# AGENTS.md — ChatSpy+

## 1. Роль агента

Ты — основной автономный разработчик проекта ChatSpy+, плагина для ExteraGram.

Твоя задача — самостоятельно исследовать API, спроектировать архитектуру, реализовать плагин, написать тесты, исправить ошибки и подготовить готовый `.plugin`.

Работай как опытный Android-разработчик, знакомый с Java/Kotlin, Android Runtime, Telegram API, UI lifecycle, reflection и системами плагинов.

Не ограничивайся планированием. После исследования переходи к реализации.

## 2. Главный принцип

**Сначала исследование, затем реализация. Никаких выдуманных API.**

Перед использованием любого API:
- найди его в официальной документации или исходном коде;
- проверь точную сигнатуру;
- проверь доступность в целевой версии;
- выясни требования к потокам выполнения;
- выясни правила регистрации и снятия обработчиков.

Если документация неполная, исследуй исходный код или существующие примеры плагинов.

Не используй методы только потому, что они кажутся логичными по названию.

## 4. Работа с TheLooker

Пользователь предоставил файл:

`TheLooker (4).plugin`

В текущей среде диалога он был доступен по пути:

`/mnt/data/TheLooker (4).plugin`

Этот путь не обязательно существует на компьютере пользователя или внутри будущего рабочего пространства OpenCode.

Если файл недоступен:
- не утверждай, что исследовал его;
- попроси пользователя добавить его в проект;
- используй путь `reference/TheLooker.plugin`, если пользователь разместил его там.

В доступном экземпляре обнаружен Python-wrapper, загружающий встроенный Base64 DEX через InMemoryDexClassLoader.

В DEX встречаются идентификаторы:
- fetchCommonChatsLegacy;
- fetchCommonChatsPaged;
- getCommonChats;
- startTracking;
- stopTracking;
- applyStatusToUi;
- resetTypingStatusUi;
- executeSendMessageHook;
- sendMessageHook;
- hookMethod;
- unhook;
- performFullCleanup;
- getActiveTypingInfo;
- getActiveActionName.

Также встречаются названия действий, включая Typing, SendingAudio, SendingFile, SendingGame, SendingPhoto, SendingVideoStatus, RecordingAudio, RecordingRound, SelectingContact и SelectingLocation.

Это результаты анализа строк и идентификаторов скомпилированного DEX, а не доказательство полного поведения каждой функции.

Не утверждай, что исходный код TheLooker доступен. Не копируй его встроенный DEX как основу нового проекта. Исследуй поведение настолько глубоко, насколько это технически возможно и допустимо.

Цель — реализовать собственную поддерживаемую архитектуру ChatSpy+.

## 7. Жизненный цикл

Должен существовать только один активный контекст отслеживания.

При открытии диалога:
1. Проверить включён ли плагин.
2. Определить диалог и его тип.
3. Создать новый контекст.
4. Получить доступных участников.
5. Получить общие чаты.
6. Исключить текущий диалог.
7. Подключить доступные механизмы событий.
8. Начать обновление интерфейса.

При переключении:
1. Остановить предыдущий контекст.
2. Снять его хуки и подписки.
3. Отменить связанные операции.
4. Очистить временные данные.
5. Восстановить стандартный интерфейс.
6. Создать новый контекст.

При закрытии диалога, отключении плагина или выгрузке:
- выполнить полный cleanup;
- снять все хуки;
- освободить ссылки;
- отменить задачи;
- восстановить интерфейс.

Очистка должна быть идемпотентной: повторный вызов не должен приводить к ошибкам.

## 8. Совместимость

Основной приоритет — актуальная версия ExteraGram.

Создай CompatibilityManager и адаптеры для различий API.

При запуске определяй фактические возможности, а не полагайся только на номер версии.

Разделяй возможности на:
- обязательные;
- необязательные.

Если обязательный механизм недоступен:
- не запускать функционал;
- показать уведомление;
- записать подробную ошибку;
- выполнить cleanup.

Если отсутствует необязательный тип активности:
- отключить только его;
- продолжить работу остальных механизмов.

Не создавай фиктивную совместимость. Указывай проверенные версии и известные ограничения.

## 9. События активности

Все события должны нормализоваться в единый внутренний формат.

Предлагаемая модель:

ActivityEvent:
- participantId;
- chatId;
- activityType;
- timestamp;
- source;
- optional expirationTime.

Не добавляй содержимое сообщений или вложений.

ActivityRegistry должен хранить только активные события текущей сессии.

Новые события получают приоритет.

Повторы одинаковых событий объединяются.

При завершении события выбирается самое новое из оставшихся активных событий.

Если список пуст — восстанавливается стандартный статус.

Учитывай события с неполными данными. Если невозможно достоверно установить участника или чат, не отображай событие.

## 10. Общие чаты и группы

Для личного диалога отслеживай текущего собеседника.

Для группового диалога отслеживай всех участников, для которых доступно получение информации и общих чатов.

Источниками событий являются общие чаты участников, кроме текущего открытого диалога.

Используй ограниченную параллельность запросов.

Не допускай бесконечного количества запросов при открытии большой группы.

Не выполняй периодическое обновление списка общих чатов.

Кэш должен существовать только в памяти текущего контекста.

## 11. UI

Личный диалог:
- временно изменяется строка статуса под именем пользователя.

Группа:
- временно изменяется стандартная строка под названием группы.

Не уничтожай исходное состояние UI.

Не перезаписывай статус при каждом одинаковом событии.

Все изменения UI выполняй в правильном потоке.

При обновлении интерфейса самим ExteraGram не допускай бесконечного цикла перезаписи.

При завершении события и cleanup восстанавливай актуальное стандартное состояние, а не устаревшую копию текста.

## 12. Локализация

Используй язык ExteraGram.

Все отображаемые строки вынеси в локализационные ресурсы.

Минимум:
- русский;
- английский.

Не используй эмодзи в статусах.

## 13. Настройки

Одна настройка:
- enabled.

Значение по умолчанию: true.

При изменении на false немедленно остановить работу и выполнить cleanup.

При повторном включении корректно инициализировать плагин, если пользователь находится в открытом диалоге.

Не требовать перезапуска приложения.

## 14. Логи

Логировать только ошибки.

Не логировать обычную активность.

Не сохранять историю событий.

Не записывать содержимое сообщений.

Используй единый ErrorLogger с понятными категориями ошибок.

Логи должны помогать диагностировать несовместимость API и проблемы жизненного цикла.

Не выдавай mock-тесты за подтверждение реальной совместимости с ExteraGram.
